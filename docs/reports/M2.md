# Milestone 2 report — blocking and baselines

Details: [M2_blocking.md](M2_blocking.md) (curve: `M2_blocking.png`), [M2_baselines.md](M2_baselines.md).
Commands: `make block` (~25 min), `make train` (~30 min), or `make m2`. MLflow: `ekam-m2-blocking`, `ekam-m2-baselines`.
Numbers below are from the **second run**, on data regenerated with the `addr_other` noise type (see Problems).

Abt-Buy 0.747, Amazon-Google 0.615, WDC 80% cc 0.430 (unseen-100%: 0.439).

**Problems found**
* *Street line was a near-identifier (generator artefact) — fixed.* In the first run LightGBM
  put ~80% of its gain on street features and removing them cost 0.032 F1 at hard (0.975 →
  0.943). New noise type `addr_other` gives some records another company's real address
  (branch / works / billing). Now identical normalised street on 62% / 32% / 13% of
  test-split true pairs (easy / medium / hard), street features are no longer in the hard
  top 5, and removing them costs 0.007 F1. Hard-level LightGBM went from 0.975 to 0.948: the
  old number was inflated.
* Identifiers barely matter after blocking (with vs without IDs: +0.003 F1 at hard).
* Splink EM blocked on PIN alone produced 1.5e8 pairs and exhausted memory → fixed (PIN + first
  token, phonetic + city); DuckDB spill now goes to `.cache/duckdb` with a 4 GB cap.
* Slow network: the CUDA torch wheel (2.75 GB) failed in uv; fetched with a resumable download,
  hash-checked against `uv.lock`, installed locally (uv sees the environment as in sync).
* Blocking, not matching, is the hard-level bottleneck: 11% of true pairs never reach the matcher.
